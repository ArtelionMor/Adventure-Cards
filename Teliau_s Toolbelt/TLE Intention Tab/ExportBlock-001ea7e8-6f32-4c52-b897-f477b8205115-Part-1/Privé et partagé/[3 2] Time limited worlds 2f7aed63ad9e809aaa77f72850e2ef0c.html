Remote settings

WorldEvent should have new fields to handle the dynamic difficulty of time limited world events

  • DynamicPower: true or false depending if this world uses a dynamic power. Dynamic power makes it so the world_power is based on the player current maximum power
    • Maximum power is computed as the player bonus power + the sum of all pets potential max power (if all upgrades are made) for the highest level pets of the player
    • If a world has DynamicPower to true, the world_recommended_power is computed as bonuspower + teampower + (world additionalPower *6)
    • The DynamicPower is computed once at event start (when the event is playable for the first time)
  • AdditionalPower: the power to add or remove on top of the world_power
  • DynamicWorldCoinMultiplier: true or false. If true the world uses the current MainWorld coin multiplier. If false it uses the world_coins_multiplier (set at event start and doesn’t update with player progress in MainWorld)
    • In case of DynamicWorldCoinMultiplier = true the world_coins_multiplier field is the offset to add or remove to the DynamicWorldCoinMultiplier (e.g. DynamicWorldCoinMultiplier = true and the player current world has 8 as WorldCoinMultiplier, if world_coins_multiplier = 1 then the event has 9 as world_coins_multiplier)
  • DynamicWorldProgressCurrencyMultiplier: true or false. If true the world uses the current MainWorld progress currency multiplier. If false, it uses the world_progress_currency_multiplier
    • Similar to DynamicWorldCoinMultiplier in terms of offset if true

Rebloom world resource logic

If a world has the rebloom mechanic it means it doesn’t respawn its resources. To handle this properly for players we want the following logic:

  • When generated, resources of a world should be displayed at the same place and of the same type (for each generation)
    • If possible we can also keep the resource progress but it’s a nice to have (e.g. I eat 50% of the resource as a player, I move and come back and I still see it at 50%)
  • Each time the resources are re-spawned through the rebloom (which is the only way to respawn resources) it should be a new random generation
    • This means if players rebloom with resources on their tile these resources are deleted to let the new respawned resource spawn
  • RandomSpawners (wheel, gift…) cycle should be reset when the rebloom happens
    • Previous RandomSpawners spawned should be kept on the map

New requirements

In 3.0.0 we introduced a requirement “tournament_inprogress” used to make stuff available when a Tournament is running. The main use case is to distribute the tournament currency only when the Tournament is live.

In 3.2, we should make this more generic and add more requirements to be able to have a wider range of behavior:

  • tournament_inprogress becomes event_in-progress to make the naming more generic and ensure it works for all events
    • We could also make it so the event_id is put in “key” and not in “value” to be more consistent with the following requirements
  • event_ended: this requirement will be used to trigger elements after an event ended
    • key: event_id

Additional unrelated requirement for 3.2:

  • minion_biome_own with key being the biome name to check if the player has at least one pet of this biome

Balancing

🕘[3.2] WIP - Time limited worlds balancing Intentions.

  • Arthur’s suggestion for balancing

    We will probably need a “Time limited world intention” tab in order to balance correctly the events. We’ll need tools to manage:

    • The difficulty:
      • We should be able to compute how long it takes to complete each world depending on its power (same thing for the leaderboard)
        • This should be broken down per player engagement in other features to low, medium, high and high-payer
        • This should allow us to set the expected difficulty for each event (e.g. low engaged players are able to collect the mid reward of the Island expedition)
        • It should be clear what type of player is able to collet what reward
    • The rewards:
      • We should be able to scale reward value according to the difficulty
      • To do so I recommend to set a value of reward per “effort”. Effort should be defined from the length of completing an event (the amount of currency to collect) and the difficulty (the world power). Those two are of course related but we can play on those to generate different type of difficulty
